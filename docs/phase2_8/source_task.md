# 工作包01：建立真正的视觉团队感知模块

## 目标

不再完全依赖Gazebo脚本直接发送掉队状态。

机器人应尽可能根据实际摄像头图像和RGB-D距离，判断游客是否处于可观测的团队区域。

## 任务1.1：审查现有YOLOX链路

检查：

```text
visitor_perception/
ros_person_detector.py
ros_depth_association.py
ros_perception_fusion.py
```

以及实际相关文件。

确认：

- YOLOX检测框来源。
- RGB图像时间戳。
- RGB-D配对方式。
- 深度有效性。
- CameraInfo。
- TF。
- 检测置信度。
- 帧率。
- 延迟。
- 人员检测稳定机制。

## 任务1.2：新增匿名人员跟踪组件

建议新增：

```text
visitor_perception/person_tracker.py
visitor_perception/team_observer.py
```

实际名称可以根据现有工程结构调整。

使用现有YOLOX检测结果实现匿名多目标跟踪。

优先采用轻量级方法：

- IoU关联。
- 位置预测。
- 卡尔曼滤波。
- 时序去抖。
- 短时遮挡处理。
- 轨迹管理。
- 跟踪置信度。
- 超时失效。

可以评估SORT或ByteTrack思想，但不要为了增加技术名词而引入大量不必要依赖。

当前不要求做人脸识别。

不要求识别游客真实身份。

不能宣称匿名跟踪ID永远对应同一个人。

## 任务1.3：RGB-D空间关联

对于实际检测到的人：

- 输出检测框。
- 输出匿名Track ID。
- 输出深度距离。
- 输出有效时间戳。
- 输出估计位置。
- 输出置信度。
- 输出观测来源。

需要区分：

```text
OBSERVED
OCCLUDED
TEMPORARILY_LOST
OUT_OF_VIEW
UNKNOWN
STALE
```

这些状态不能简单合并成“游客掉队”。

## 任务1.4：明确视觉盲区

现有机器人主要使用前向相机。

如果游客位于后方，可能完全不可见。

这种情况下：

**不能用Gazebo真值代替机器人视觉。**

必须返回：

`UNKNOWN` 或 `OUT_OF_VIEW`

不能把不可见游客直接判定为已离队。

如果当前硬件配置无法实现可靠后方视觉跟踪：

1. 保留视觉模块。
2. 建立明确的视觉覆盖分析。
3. 使用保守团队确认策略。
4. 允许机器人在安全停靠点执行有限观察。
5. 不得为了获取团队视野而在正常导航中执行未经验证的危险转向。
6. 如需未来增设后向相机，单独列为硬件扩展方案。

不能为仿真便利虚构真实temi不存在的摄像头能力。

# 工作包02：重构团队掉队判断的数据来源

这只是场景脚本触发状态机。

```text

         ↓
RGB-D模拟相机
         ↓
YOLOX人员检测
         ↓

         ↓
团队状态观察器
         ↓

         ↓
```

同时：

```text

         ↓
实验评估器
```

Gazebo真值只能作为实验评价数据，不得悄悄进入视觉算法决策。

将团队状态来源明确区分：

```text
camera_observation
vision_tracker
simulation_script
manual_operator
unknown
```

只有具有适当观测证据的状态，才能作为自主视觉团队判断依据。

脚本团队状态可以继续用于：

- 三维人物运动。
- 测试场景控制。
- 实验真值。
- 显式标记的业务演示模式。

但不得在视觉验收模式中直接触发掉队。

如果相机无法观察后方游客，应明确报告：

**视觉覆盖不足，无法独立确认后方队伍人数。**

可以采用人工确认或固定观察点机制。

不要通过伪造视觉数据强行使测试通过。

# 工作包08：真正完成速度标定

目前阶段2.7中：

配置速度为0.3m/s，但规定标定窗口实际接近零。

必须首先分析：

- 标定是否发生在机器人启动前。
- Nav2是否已经开始导航。
- 是否选择了转弯或停车区域。
- 是否存在速度限制。
- 是否误用了时间戳。
- odom是否新鲜。
- 机器人是否已经到达目标。

## 修复方案

建立独立直线路段速度标定任务。

确保机器人真正进入稳定运动状态后，再开始采样。

对实际速度进行验证。

建议覆盖：

```text
0.3 m/s
0.5 m/s
0.7 m/s
```

注意：

这是仿真速度档位，不代表真实temi已经允许或达到这些速度。

每个档位记录：

- Nav2配置上限。
- Nav2参数读取结果。
- cmd_vel。
- odom。
- 实际中位速度。
- 速度误差。
- 稳定窗口长度。
- 是否达标。

未达标的速度档不能进入已验证结果统计。

如果Nav2受路线、障碍、加速度或底盘仿真参数限制达不到目标，记录实际可达到速度，不得修改odom数据。
