## P0：实体 temi 接入与安全验证（获得设备后优先）

1. 核对实际 temi 型号、Launcher/系统版本与 `1.139.0` SDK 兼容性；在可人工随时停止、无人或少人、空旷受控场地安排首次测试。不要关闭机器人原有安全及避障设置。
2. 安装 Bridge Debug APK，先只验证网络握手、认证、SDK Ready、位置、电量、速度和导航/TTS Listener 的实际事件；不发运动命令。确认断线/重连时状态正确，不自动执行旧任务。
3. 由展厅工作人员和开发人员建立真实地图并保存真实入口、展区、互动区、出口及允许返回的安全位置，更新 `temi_location`，核对姿态坐标系、单位及定位可靠性。不得把 mock_map 中任何坐标当成实机位置。
4. 在安全场地分别验证短距离命名地点导航、正常终态、暂停/停止、取消、低电量、电量变化、服务断开、网络断开与恢复、人工停止以及 TTS。重点确认停止后真正静止、速度回调/导航终态可靠、没有旧任务重放；必要时先修正 Android 本地断线保护。
5. 根据设备真实行为确认任务超时与真实安全边界，配置充电座/返回地点和电量策略。通过后再将 `gateway.backend` 从 mock 切换到 websocket 并测试固定路线。

**验收门：** 实体运行记录、可重复的连接与停车验证、真实保存地点映射、人工接管演练通过后，才允许面向游客运行。网络 ACK、ROS Action CANCELED、APK 编译或虚拟测试均不能替代物理安全验证。

## P1：无实机期间可并行开发游客感知

- 建立 `visitor_perception` ROS2 包，先使用公开或经许可的视频/模拟人数数据，设计游客到来、人数统计、团队跟随状态与掉队事件。
- 优先使用匿名人数/区域计数，不默认采集人脸身份；设计同意、退出和隐私处理。以后获得硬件再校准摄像头视角、遮挡、移动人群和检测延迟。
- 将感知结果映射现有 `heritage/tour` 控制：到来后请求开启迎宾，明确同意/拒绝，掉队后暂停并经人工或可信状态恢复。无硬件时用录制或模拟事件测试，不宣称传感器实测。

**验收门：** 离线数据集上的计数准确率、误报率、延迟指标有记录；与现有状态机联动测试通过，不误触发运动任务。建议这是缺少实体设备时最值得开始的独立模块。

## P2：非遗知识库、语音交互和 QA

- 建立 `heritage_knowledge` 包，整理展厅授权资料、官方非遗条目和工作人员审核内容；保存来源、版本、展区标签及讲解层级。
- 先验证基于已知文本的问答检索、无依据时的拒答与引用来源，再接入实际 temi ASR/TTS（官方 `AsrListener` 已在阶段一核对，尚未实现语音输入）。
- 将问答接入 QA 状态，支持访客打断、回答结束继续路线；明确超时、噪音、口音、拒绝回答与人工转接逻辑。

**验收门：** 每个展区有经过审核的讲解内容、覆盖典型问答的离线测试集，答案可追溯，不捏造展品或地域历史；真实 ASR 体验另行测试。

## P3：真实导览异常恢复与展示部署

- `heritage_tour_manager` 在已验证的单条路线基础上扩展散客/团队策略、暂停断点、低电量充电返回、限定次数重试、明确人工回收及掉队策略。不要提前引入复杂多智能体或强化学习。

**验收门：** 连续多轮实体导览、断线/低电量/拒绝/掉队等场景具备真实记录；机器人运动与人工接管安全边界经过工作人员确认后再部署。
