# 游客感知 2.1：Mock 数据驱动设计

## 目标与范围

先新增独立的 ROS2 `visitor_perception` 包，使用可重复的模拟匿名人数观测验证游客到来、人数统计、团队掉队及重新集合的判断。无需摄像头、Android 或实体 temi。本阶段不控制运动、不自动同意导览、不自动恢复暂停任务；2.2 再接入既有 `heritage/tour` 服务，2.3 再更换为真实视觉人数输入。

## 模块与数据流

- `visitor_monitor.py`：纯 Python 状态判断逻辑，接受非负整数人数和单调时间；可独立测试。
- `ros_visitor_node.py`：订阅 `heritage/visitor/count`（`std_msgs/Int32`，模拟当前观测人数）与 `heritage/visitor/expected_count`（`std_msgs/Int32`，显式设置本次队伍预期人数），发布 `heritage/visitor/status` 和 `heritage/visitor/events`（`std_msgs/String` JSON），沿用现有导览状态的 JSON 约定。
- `main.py`：独立 ROS2 节点入口；`config/system.yaml` 增加感知本地配置。
- `scripts/demo_mock_visitors.py`：在本机隔离 ROS Domain 下发送模拟人数序列，记录状态和事件，不调用导航服务。

输入源只提供匿名区域人数，不使用人脸、身份识别或个体追踪。以后真实视觉模块替换模拟人数生产者时保持 ROS2 输入契约不变。

## 状态与判断规则

初始状态：观测无效、人数未知、预期人数 0（未跟踪团队）。默认要求连续 3 个同值观测才确认稳定人数；连续样本之间无超过 2 秒的观测间隔。单次噪声或短时遮挡不触发事件，仍保留上一次稳定人数。若超过 2 秒未收到合法观测，发布数据过期状态并清空连续计数；等待新的稳定观测后恢复有效，不把无数据解释为零人。

- 稳定人数由 0 或未知变为正数：单次 `arrival`；随后稳定人数为 0 时发布 `departure`。首次有效的零人观测不发布离开事件。
- 预期人数由外部显式设置；0 清除本次团队，正数启动人数不足判断。相同值重复输入不产生副作用；变化时重置团队事件状态，在下一次稳定观测后评估。团队人数只代表匿名区域统计，不保证实际成员身份或跟随机器人。
- 观测有效且稳定人数低于预期人数：发布一次 `visitor_lost`，直到稳定观测人数重新达到预期值才发布一次 `regrouped`。未设置预期人数时不产生团队事件。达到预期人数只是人数恢复，不是自动恢复机器人运动的授权。
- 过期或尚未稳定时不产生到来、离开、掉队或集合事件。数据断流发布一次 `data_stale`；重新稳定发布 `data_restored`（仅实际进入过期状态之后）。保留上一有效人数与团队事件状态以判断恢复后的变化，不因短暂断流重复事件。
- 负数输入无效，不刷新观测有效期并清空当前连续计数；配置稳定样本数为正整数、超时为有限正数。状态字段 `valid`、`people_count`（无有效观测时为 null）、`expected_count`、`group_state`（`untracked`/`unknown`/`following`/`lost`）与 `source: mock` 明确区分未知和模拟观测。预期人数 0 时始终为 `untracked`；启用团队且观测过期或尚未完成首次评估时为 `unknown`。

## 验收标准

1. 新 ROS2 包可以独立通过 colcon 构建和安装，节点与测试均使用现有项目工具链，不新增系统级依赖。
2. 自动化覆盖稳定到来/人数变化/离开、噪声过滤、显式队伍人数、掉队与集合去重、过期/恢复/非法输入，以及不跟踪时不误报队伍事件。
3. 实际 ROS2 Topic 回环验证并运行独立模拟脚本：0 人 → 3 人到来 → 设置预期队伍 3 人 → 2 人掉队 → 恢复 3 人 → 清除队伍 → 0 人离开；记录每次状态及事件。另验证数据断流不会被判为游客离开或恢复队伍。
4. 复跑第一阶段 Linux 测试，保存真实执行日志和新增测试数，更新 README、开发日志与游客感知使用说明。

本次验收只衡量模拟数据和 ROS2 状态逻辑，不报告视觉识别准确率、真实人数统计准确率或传感器延迟；这些属于 2.3 或实体硬件验证。
