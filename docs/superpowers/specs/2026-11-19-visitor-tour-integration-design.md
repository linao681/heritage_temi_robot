# 游客感知与导览联动（2.2）设计

## 目标与边界

在无实体 temi 的情况下，让 2.1 的匿名 Mock 人数观测真正驱动既有 ROS2 导览状态机。验收路径为一次主动迎宾、明确同意、固定导览、掉队或感知异常后暂停、人工确认恢复、任务完成。现有独立感知、手动导览、Android Bridge 均保留；不涉及视觉模型或实机运动验证。

## 方案选择

1. **推荐：在导览节点内首次接入感知协作策略。** 感知节点只发布数据，导览管理器复用已有 `start`、`consent`、`visitor_lost`、`resume` 与控制优先级，感知和人工控制在同一 asyncio loop 串行处理。避免额外节点通过 ROS 服务产生延迟或旧任务重放。
2. 独立协调节点异步调用导览服务。部署更松耦合，但需额外解决任务关联、服务超时、状态更新与人工接管的竞争；本阶段不引入该复杂度。

## 联动规则

- **默认关闭，Mock 专用。** 用户显式启用联动模式并通过 `heritage/tour/arm_visitor` Trigger 服务准备一次迎宾；只在机器人状态确认为 `mock_map`、连接正常、静止且电量已知并高于阈值时允许。禁用模式保留原有手动服务行为。若联动会话中来源不再是 Mock，终止协作并按既有通信失效流程处理。`mock_map` 只是开发环境识别标志，不是生产环境身份认证。
- **一次触发。** 每次 arm 后必须观察到新鲜、稳定的零人数再观察到稳定正人数，才触发迎宾；启动尝试立即消费 arm，不循环重试。只有确认旧队伍预期人数为 0 后才允许 arm。同一批游客持续存在、拒绝导览、任务结束、人工接管或断线均不自动开启新任务，需工作人员再次 arm。同意服务仍为显式人工输入；若游客已在场，可使用既有手动模式，显式手动 start 会解除尚未消费的 arm，但不会把正在运行的辅助任务换成手动任务。
- **团队人数。** 自动迎宾时以稳定正人数记录本次预期队伍人数，通过 `heritage/visitor/expected_count` 发布给感知节点。只有收到匹配预期人数、稳定且新鲜的 `following` 状态，才接受 `heritage/tour/accept`，并再次确认连接/电量及状态守卫；拒绝无需感知有效。迎宾期间低电量或掉线结束本次辅助任务，不执行未经同意的导航。普通手动模式保持旧行为。
- **掉队和感知失效。** 已同意的辅助导览期间，稳定人数不足触发现有掉队暂停；非法/过期数据、长时间没有稳定人数、感知节点心跳丢失或预期人数不一致同样暂停。短时抖动在阈值期限内不会被误认为掉队。暂停必须先按既有状态机结算活动 Action/STOP；不绕过 STOP 结果，不抢占通信断开、人工接管、取消或低电量返回等已有高优先级保护。
- **恢复。** `regrouped` 或 `data_restored` 只更新可恢复条件，不调用 `resume`。只有当前处于 PAUSED、明确收到人工 `resume`、感知新鲜稳定、人数达到本次预期且机器人已连接并确认静止，才继续同一未完成路段。未满足条件时拒绝请求，并保持暂停；不会因为之后数据恢复而执行旧恢复请求。
- **收尾。** 完成、拒绝、取消、人工接管、错误或关闭后清除本次预期人数（发布 0），关闭 arm，重置联动会话。显式手动停止/接管始终优先；未开始的 armed 状态也可被取消或人工接管解除。

## 数据接口和模块职责

沿用 Topic `heritage/visitor/status`、`heritage/visitor/events`、`heritage/visitor/expected_count`。感知状态新增两个向后兼容 JSON 字段：`stable` 表示当前连续观测达到稳定阈值；`stable_fresh` 表示最近一次稳定确认未超过现有 2 秒超时。即使合法原始人数持续抖动导致 `valid=true`，`stable_fresh` 到期也应识别为感知不可靠。状态定时发布用于感知心跳；导览节点按本机单调时间记录接收时间并监测心跳，辅助状态中显示 armed、active、expected_count、可接受/恢复条件及等待原因。决策基于最新状态快照，事件 Topic 保留供日志展示，不直接执行命令，避免事件重复或延迟造成误触发。无感知数据时不得解释为零人。

配置 `tour.visitor_assist_enabled` 默认 `false`，`tour.visitor_status_timeout_sec` 默认 1 秒（感知状态默认 0.2 秒周期）。只有启用模式才创建感知联动入口及订阅；演示通过专用配置开启，不修改实机部署默认设置。所有验证均在独立、本机 ROS Domain 下进行。

## 验收

1. 测试默认关闭不会因人数变化启动任务，启用未 arm 也不主动迎宾；arm 后新鲜零到正的边沿只触发一次，拒绝或人工接管不重启。
2. 在收到人工同意前无导航；未收到队伍人数匹配的新鲜稳定状态时 accept 失败。测试低电量、连接中断及来源不符时禁止辅助导览启动。
3. 真实 ROS2 集成测试覆盖 Mock 导航过程中掉队、断流/心跳丢失、抖动长期不稳定导致暂停；核对虚拟机器人停止，自动恢复被禁止，人工恢复仅在满足条件后执行且继续原路段。验证取消、人工接管和低电量控制优先级。
4. 运行独立 Mock 感知 + Gateway + Tour Manager 三节点端到端演示，记录迎宾、同意、暂停、拒绝不安全恢复、重新集合、人工恢复及八站完成。报告保留状态、事件与耗时；逐步测试，最终复跑现有 103 项 Linux 测试及新增集成用例。
