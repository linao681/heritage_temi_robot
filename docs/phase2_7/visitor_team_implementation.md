# 三人游客跟随实现记录

当前实现先在入口生成三位游客，沿明确标记的接待编队路径形成队列，后续沿 Gazebo 机器人位姿历史步行。游客通过 SetEntityState 移动，位置由 Gazebo 回读；网页呈现同一组实体。它是脚本游客行为，不是相机识别或真实人员跟踪。

三人队列目标间距分别为机器人后方 2.4、3.5、4.6 m。每个游客独立限制步速，沿弧长插值经过转角，检查地图占据、机器人距离和同伴间距。转角采用可达的安全跟随目标，必要时在地图网格上局部绕行；没有安全位置时停止游客动作。机器人位姿跳变会中止进程。初始接待路径是脚本编队，不描述为机器人真实走过的路径。

队尾放慢至 0.04 m/s，路径落后超过 1.5 m 后调用已有 visitor_lost 服务。集合恢复游客步速，不发送机器人恢复命令。导览服务和网页恢复入口要求队伍新鲜且集合完成。该限制仅在收到脚本队伍状态后启用。

启动方式（在空闲域和端口上，启动前先构建）：

```bash
cd /home/linao/heritage_workspace/heritage_temi_robot
bash scripts/start_full_visitor_demo.sh
```

默认 Domain 229，Gazebo 端口 11367，页面地址为 http://127.0.0.1:8098/ 。完整运行器等待全部系统预检与三人编队完成后，模拟游客同意与操作员集合确认，调用真实 ROS 服务执行路线；所有模拟控制均写入 events。队伍动作状态写入本次系统日志目录的 visitor_team.jsonl，网页实时采样写入 live_evidence.jsonl，终态写入 report.json。演示语音可在网页启用，依赖浏览器语音支持；后端是有时长的模拟播报与字幕，不是实体 temi TTS。

网关、速度策略、恢复、游客轨迹与网页接口最终定向回归 97 passed（`tests/visitor-full/targeted_final.log`）。构建七包成功。实跑发现的并发 STOP 拒绝问题已改为同一次停车共享确认，并有直接并发和 ROS 服务回归。
