# zone_1 触发器诊断记录

本次是调度诊断，不计作 E05 完整实验，也不作为通过或失败的安全性能样本。

- 系统在隔离 Domain 232 通过完整预检。
- Gazebo 入口静态游客真值已生成；导览启动后，运行器曾完成 zone_1 并继续到 zone_3。
- 动态场景进程仍等待目标 `zone_1`，没有生成人物，也没有 `scenario/truth.json`。CSV 中人物真值字段为空。
- 发现时停止了本轮测试，以免让场景进程继续等待超时。报告保留为 `RUNNING`，CSV 和事件记录原样保留。
- 根因是运行器在“接受游客同意并启动导览”后才创建动态人物进程；短的 zone_1 导航状态事件可以在子进程建立 ROS2 订阅前结束。

对应代码正在调整为：在 `WAITING_CONSENT` 时先启动动态场景子进程，等待子进程完成清理并报告已进入导航监听，再调用同意服务。该顺序不允许人物在导览导航启动前移动，因为子进程仍须观察到匹配 UUID、目标和新鲜 odom 后才注入场景。
