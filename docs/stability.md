# 4.3 本机 Mock 稳定性与异常恢复验收

本阶段复用一键启动，不增加实体控制权限。连续演练保留同一组进程、虚拟位置和电量，逐轮记录状态。默认待机不自动发起任务；异常时不自动重启、重试、接受同意或重放旧任务。

## 复现命令

在项目根目录，已构建 ROS2 六个包后：

```bash
bash scripts/start_mock_system.sh --headless --demo --rounds 6
```

回归测试：

```bash
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
ROS_LOCALHOST_ONLY=1 .venv/bin/python -m pytest -q tests
```

测试仅在隔离本机域运行，不对真实机器人、其他 ROS Domain 或外部网络注入故障。

## 五分钟待机实测

独立 Domain 212 在默认待机模式持续运行 300.403 秒（`timeout --preserve-status --signal=TERM --kill-after=50s 300s bash scripts/start_mock_system.sh --headless --domain 212`）。期间未出现状态心跳超时或子进程异常；最终 IDLE、无访问记录、人数未知、虚拟位置入口、虚拟电量 100%、虚拟静止，四个子进程均正常退出。[待机运行报告](runs/mock-system-20261120-171654-373005/report.json)。

## 异常演练

- 在导览前往潮绣时终止本测试直接启动的 Mock Gateway。监督程序检测进程退出，报告本轮失败并有界关闭剩余节点；不重复启动。
- 首轮实际发现导览管理器的 12 秒关闭期限不足以覆盖 STOP 通信、旧 Action 取消及清理。原失败报告：所有其他进程退出，但导览节点被迫终止。[首次报告](runs/mock-system-20261120-171408-049383/report.json)
- 修正退出等待预算后，故障仍被明确报告为失败，但四个本次启动的节点均以退出码 0 结束，无强制终止。导览节点日志仍明确标记 STOP 超时、停车未确认、旧 Action 未确认终止；不能把 ROS 节点退出当成物理停车。[最终故障报告](runs/mock-system-20261120-172002-722643/report.json) · [导览日志](runs/mock-system-20261120-172002-722643/tour_manager.log)
- 同一 Domain 下由测试明确重新启动，默认进入 IDLE，访问记录为空、虚拟位置入口、静止，没有重放旧任务。[恢复待机报告](runs/mock-system-20261120-172019-249052/report.json)
- 另复测已有 ROS2 通信断开/重连用例：断开后进入 ERROR，重新连接不会自动继续旧导览，需人工发起新任务。

## 验收边界

这是本机 Mock 连续运行和故障处理验证。多轮完成不代表长日、真实人流、实体停车、续航、传感器及网络安全已经通过现场认证。生产级长期稳定性需在真实设备和受控场地测试，记录实测数据。
